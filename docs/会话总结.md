# Video Switch 会话总结

## 当前阶段

- 阶段：步骤 11，自动测试与性能优化（第 1 项已完成）
- 状态：已完成，等待用户验收
- 更新日期：2026-10-11

## 项目目标

开发一款面向实际使用的桌面视频格式转换器，支持视频信息展示、缩略图、
FFmpeg 命令行转换、任务进度、取消、错误提示和批量处理。最终代码上传
GitHub，并在 Releases 中提供 Windows 运行包。

## 已确认技术选择

- 使用 Python 3.12+ 和 uv 管理项目。
- 使用 PySide6-Essentials 构建桌面客户端。
- 使用 Qt Widgets、QSS 和 QProcess。
- 使用 ffmpeg/ffprobe 命令行，不接入 FFmpeg API。
- 运行时不调用任何远程 API。
- 使用 pytest、pytest-qt、Ruff 和 PyInstaller。
- 最终打包 Windows 客户端并发布到 GitHub。

## 步骤 7 反馈修复（转换历史与取消续转）

- 转换历史改为按源视频分组，只显示当前选中视频的记录，删除任务时可选择
  同时删除关联历史，并支持删除单条历史。
- 历史条目显示转换类型、输出目录、状态、文件大小和实际转换耗时。
- 兼容缺少 `source_key` 的旧历史文件，避免启动崩溃。
- 取消状态增加“继续转换”：MP4、MKV、WebM、MP3、WAV 且时长超过 30 秒时
  按 30 秒分段转换，取消只丢弃未完成的当前分段，继续时跳过已完成分段，
  全部完成后用 `concat` 合并为最终输出。
- GIF 和短于 30 秒的视频取消后按钮显示“重新转换”，语义与行为一致。
- 取消状态增加删除图标按钮，用于丢弃这次取消结果并回到“已读取”，
  转换历史仍然保留。
- 使用 70 秒 720p 视频完成真实续转验证：取消时保留 1 个分段，
  继续转换从 43.5% 开始，输出时长 70.02 秒，分段目录清理干净。
- “正在转换”行右侧恢复显示实时信息（如 `1.24x · 剩余 01:28`）：
  原先详情标签宽度被布局压成 0 像素，文本被省略为空，现已改为占满行尾并右对齐。
- 取消状态详情改为显示 `已保留 XX% 进度，可继续转换`，
  删除取消状态前若有保留分段会弹出确认框说明会丢弃多少进度。
- 优化取消转换的响应速度：原先取消要等 1500ms 兜底强杀，实测延迟 1516ms；
  为避免被丢弃的分段浪费时间，兜底时间缩短到 250ms，实测延迟降到 266ms。
- 删除取消状态的按钮换用用户新提供的描边叉号图标，并移到按钮行最右端，
  与左侧操作按钮拉开距离，降低误点概率。
- 只有真正保留了已完成分段时才显示“已保留 XX% 进度”，
  取消于第一个分段之前只显示“可继续转换”，删除时也不再弹出无意义的确认框。
- “转换完成”状态同样提供最右侧的清除按钮，点击后任务回到“已读取”，
  输出文件和历史记录都会保留，方便重新用其他参数转换同一个视频。

- 转换设置面板底部新增“批量转换”按钮，按当前设置依次转换队列里的全部视频。
- 队列标题右侧在批量进行中显示进度，例如 `批量 2/3`，队列条目逐条显示
  “转换中 XX%”“已完成”“失败”等状态。
- 批量开始前统计可转换任务；无法读取媒体信息的视频直接跳过，不阻塞整批。
- 如果队列里已经存在转换完成的视频，会先询问“全部转换”还是“跳过已完成”，
  重新转换会生成新的输出文件，不会覆盖已有文件。
- 批量进行中“开始转换”隐藏，按钮行保留“批量转换（禁用）”和“取消全部”，
  点“取消全部”会取消当前文件并清空剩余队列，已完成的视频输出仍然保留。
- 批量结束后在底部汇总“成功 / 失败 / 已取消 / 跳过”的数量。
- 批量过程中移除待转换任务会同步从队列里剔除并计入跳过，清空队列会终止整批。
- 使用真实样本完成端到端验证：3 个任务中 2 个真实视频转换成功、
  1 个非视频文件被跳过，底部提示为“批量转换完成（共 2 个）：成功 2 · 跳过 1”。

## 步骤 8 反馈修复（进度崩溃与批量入口重做）

- 用户报告两个严重问题：切换任务后历史面板仍显示上一部视频的记录；
  批量转换后“开始转换”按钮消失，只剩批量转换按钮。
- 根因：ffmpeg 第一个进度块把 `out_time_us` 写成 `AV_NOPTS_VALUE`
  （`-9223372036854775807`），旧代码当成真实时间戳，算出 `-230584300921369%`
  的进度，`QProgressBar.setValue` 溢出抛异常。异常打断 `_on_task_selected`，
  历史面板来不及刷新；批量推进时同样在这里中断，`batch_running` 卡在 True，
  按钮就再也回不来。
- 修复：解析层忽略负数时间戳与 `AV_NOPTS_VALUE`，分段进度增加 0 下限钳制，
  界面层再加一道 `_progress_percent` 钳制。
- 历史面板增加 `_history_source_key` 绑定并在预览更新前同步，
  保证面板永远属于当前选中的视频。
- 批量流程改为两步弹窗：先勾选视频（未读取完成的显示原因且不可选，
  已完成的默认不勾选），再确认参数（格式、画质、分辨率、帧率、
  视频编码、CRF、音频编码、音频码率、输出目录），确认后才开始。
- “批量转换”按钮固定放在“开始转换”右侧并始终可见，
  批量进行中只置灰，不再隐藏任何按钮。
- 新增 400ms 批量看门狗：批量标记进行中但转换进程已停止时自动继续或收尾，
  单点异常不会再造成界面卡死。
- 用真实 MP3 批量流程复验：无双视频串记录、批量正常收尾、两个按钮均在位。

## 步骤 9 异常处理与恢复

- 新增 `services/error_messages.py`，把 FFmpeg/ffprobe 的原始英文报错翻译成
  可执行的中文提示：磁盘空间不足、输出目录无权限或被删除、源文件被移动或删除、
  文件损坏无法解析、编码器不可用、参数组合不被支持、输出文件被占用；
  无法归类时给出通用提示并附上日志最后一行。原始输出仍然完整保留在“转换日志”里。
- 转换开始前检查源文件是否还在，被移动或删除的任务直接给出
  “源文件已被移动或删除，请重新导入后再转换”，不再等 FFmpeg 报错。
- 新增“重试失败项”按钮：只在队列里存在失败任务且当前空闲时出现，
  点击后仅重新转换失败的任务，并复用批量转换的参数确认弹窗。
- 分段信息持久化到 `conversion/resume_dirs`（源视频指纹 → 分段目录、设置指纹、分段数）。
  应用被关闭导致转换中断后，下次启动会把任务恢复成“已取消 + 可继续”，
  显示已保留的进度，点击“继续转换”即可接着完成；清除取消状态时会同步删除记录。
- 恢复流程必须等 ffprobe 读完媒体信息再切换状态，否则任务会跳过读取环节，
  这个问题在端到端验证中被发现并修正。
- 新增 `services/crash_handler.py`：未预期异常写入
  `%APPDATA%/VideoSwitch/Video Switch/logs/video-switch.log`，
  超过 512KB 自动截断，并在界面上提示日志位置、可直接打开日志目录。
- 端到端验证：70 秒视频在 52% 取消 → 保留 1 个分段 → 模拟重启后被识别为
  “已取消、可继续、进度 43%” → 继续转换完成并清理分段；
  另用损坏文件验证失败文案为“视频内容无法解析，文件可能已损坏或格式不受支持”。

## 步骤 10 第三批（体验细节收尾）

- 对比度实测：用脚本按 WCAG 公式计算 18 组“文字色 × 背景色”，
  发现浅色 muted 在选中行上只有 4.06:1、深色 primary 只有 3.80:1。
  微调浅色 muted 为 `#5f6d80`、浅色 primary_soft 为 `#eef4ff`、
  深色 primary_soft 为 `#152539`、浅色 danger 为 `#d42020` 后全部达到 4.5:1。
- 历史条目从四行压缩为两行（格式 → 文件名 / 时间 · 状态 · 大小 · 耗时），
  输出目录等排查信息移入 tooltip，条目高度 54 → 44 像素。
- 缩略图首次生成时用 180ms 淡入，替代此前的瞬间替换。
- 进度刷新按任务节流到 200ms 一次（内部数值始终实时），
  队列任务较多时滚动更跟手。
- 七个图标按钮补齐 `accessibleName`，主题切换与清除状态按钮在文案变化时同步更新。
- 首次运行且未找到 FFmpeg 时弹出非模态引导窗口，提供“打开设置”入口，
  只提示一次（`ui/ffmpeg_guide_shown`）。
- 拖拽悬停反馈加强：预览区同时改变边框与底色。
- 高 DPI 复查：在 125% / 160% 缩放下渲染核对，发现写死 104 像素的按钮宽度
  会把主按钮挤到裁字，于是改为按内容定宽（`Fixed` 尺寸策略 + 最小宽度），
  160% 下按钮行完整显示。
- 修复“MP3 转完再转 GIF 时进度直接 100%”：运行器用 `_completed_duration`
  记录已完成时长，分段转换（MP3）结束后该值等于总时长，
  而单进程分支（GIF）没有在 `start()` 里重置它，导致第一次进度上报就被钳到上限。
  现在每次转换都重置已完成时长与分段时长；真实执行 MP3 → GIF 验证，
  GIF 进度从 0.00% 正常递增。
