本文记录步骤 11 的实测数据。所有数字都是在开发机上跑出来的真实结果，

## 一、测试与覆盖率基线

统计命令：

```powershell
uv run pytest --cov=video_switch --cov-report=term-missing
```

调整前的基线是 **总体 83%**，其中服务层最弱的两块是
`conversion_runner`（50%）与 `media_probe`（65%）：它们依赖 `QProcess`，
以前的测试只覆盖了纯函数部分。

步骤 11 第 1 项补了一套不启动真实进程的服务层测试（`tests/test_services.py`），
用替身进程对象驱动状态机，结果如下。

### 仍然留白的地方（有意为之）

- `app.py` 与 `__main__.py`（入口）：需要真正启动事件循环，属于步骤 11 第 2 项
  “端到端测试转正”的范围。
- `conversion_runner` 里真正拉起子进程的分支（`_start_process`、`_read_stderr`、
  `_force_kill` 等）：这些必须用真实 ffmpeg 才有意义，同样放到端到端测试里。
- 字体注册、DPI 变化等平台相关分支：依赖具体屏幕设置，以人工渲染核对替代。

### 补测过程中顺手修掉的两个问题

1. `media_probe` / `thumbnail` 在“进程从未启动”的情况下调用
   `signal.disconnect()`，Qt 会抛出 `RuntimeWarning`。现在统一走
   `services/qt_process.detach_process()`，显式静默该警告并集中处理。
2. 新增的跑分测试暴露了 `_ToolProbe` 的“重复完成”行为（同样一条结果被发送两次），
   已用测试固定：完成后再收到结果不会重复上报。

## 三、端到端测试转正（第 2 项）

开发过程中在 `.tools/` 下写过一批临时验证脚本（续转、批量、异常恢复、
MP3→GIF 进度、取消延迟）。它们已经整理成 `tests/e2e/` 下的正式测试：

| 文件 | 覆盖内容 |
| --- | --- |
| `test_e2e_conversion.py` | 真实转换产出可播放文件并核对时长；纯音频输出不含视频流；损坏文件给出中文提示 |
| `test_e2e_resume.py` | 分段转换中途取消 → 保留分段 → 继续转换 → 输出完整且分段被清理 |
| `test_e2e_batch_window.py` | 走完整窗口链路（导入 → ffprobe → 批量转换 → 历史分组），
  2 个正常文件成功、1 个损坏文件跳过 |
| `test_e2e_regressions.py` | MP3（分段）转完再转 GIF（单进程）进度从头开始；取消在 1 秒内生效 |

### 运行方式与耗时

```powershell
uv run pytest              # 全部测试，约 15 秒
uv run pytest -m "not slow"  # 只跑单元测试，约 8 秒
```

实测：**181 passed in 14.8 秒**。

### 自动跳过

端到端测试通过 `tests/e2e/conftest.py` 里的 `ffmpeg_path` / `ffprobe_path`
夹具查找工具：优先用仓库内的 `.tools/ffmpeg/bin`，其次查系统 PATH。
找不到时直接 `pytest.skip`，不会因为环境缺失而失败。
把 `.tools/ffmpeg/bin` 临时改名后实测：`7 skipped in 0.11s`。

测试输入不依赖仓库里的示例文件：每个用例用 FFmpeg 的 `testsrc2` 现场生成
小尺寸片段（320×240、15fps），所以换一台机器也能跑。
