# 开发决策记录

本文档记录项目中的关键选择、原因、备选方案和用户反馈。后续每个步骤继续追加，
不覆盖旧记录。

## DR-001 使用桌面客户端

- 状态：已接受
- 背景：审核会优先查看界面选型，纯网页方案不符合客户端关联要求。
- 决策：使用 PySide6 构建桌面客户端。
- 原因：当前项目为 Python，桌面能力和本地文件处理直接，开发风险低于 Electron
  或 Tauri。

## DR-002 使用 FFmpeg 命令行

- 状态：已接受
- 背景：题目允许通过 ffmpeg 命令行完成转换。
- 决策：使用 ffmpeg/ffprobe 可执行文件，不接入 FFmpeg API。
- 原因：开发速度快、进程隔离清晰、无需编译原生库。

## DR-003 不在运行时调用远程 API

- 状态：已接受
- 背景：题目要求使用 AI 辅助开发，没有要求应用提供在线 AI 功能。
- 决策：应用完全本地运行，不调用大模型、云转换或账号 API。
- 原因：保护视频隐私、避免密钥和服务器成本、降低演示失败风险。

## DR-004 使用 PySide6-Essentials

- 状态：已接受
- 背景：完整 PySide6 包含 WebEngine、PDF 和 Addons，体积较大。
- 决策：只安装 PySide6-Essentials。
- 原因：Qt Widgets、QtCore、QtGui 和 QProcess 已覆盖当前项目需求。

## DR-005 使用 uv 管理环境

- 状态：已接受
- 背景：用户使用 uv，并且需要可复现依赖。
- 决策：使用 `pyproject.toml` 和 `uv.lock`。
- 原因：环境初始化、依赖锁定和命令执行统一。

## DR-006 使用三栏式桌面工作区

- 状态：已接受
- 背景：应用同时存在任务队列、视频信息和转换设置三个主要工作区域。
- 决策：采用左侧任务队列、中间视频信息、右侧转换设置的单窗口布局。
- 原因：用户可以在一个界面内完成检查、配置和执行，不需要频繁跳转页面。

## DR-007 提供浅色和深色主题

- 状态：已接受
- 背景：桌面工具需要在不同使用环境下保持清晰和舒适。
- 决策：浅色主题作为默认主题，深色主题通过顶部按钮切换并保存。
- 原因：提高界面完成度，并验证所有自定义控件具备清晰的主题对比。

## DR-008 显式注册 Windows 中文字体

- 状态：已接受
- 背景：Qt 在部分运行环境中无法自动发现 Windows 中文字体。
- 决策：启动时尝试注册系统的 Microsoft YaHei 字体文件。
- 原因：避免中文界面出现方框或缺字，同时仍使用系统字体，不额外分发字体文件。

## DR-009 FFmpeg 使用分层查找

- 状态：已接受
- 背景：开发环境和最终打包环境的工具位置不同，用户也可能已经安装 FFmpeg。
- 决策：依次查找用户配置路径、应用内置目录、开发工具目录和系统 PATH。
- 原因：兼顾可移植性、离线运行和用户手动修复。

## DR-010 异步验证工具版本

- 状态：已接受
- 背景：执行外部程序可能失败或长时间无响应，同步检测会阻塞界面。
- 决策：使用 QProcess 异步执行 `ffmpeg -version` 和 `ffprobe -version`，并设置超时。
- 原因：保证检测过程界面保持响应，同时统一处理路径错误和版本异常。

## DR-011 开发用 FFmpeg 不提交仓库

- 状态：已接受
- 背景：完整 FFmpeg 二进制体积较大，不适合直接进入 Git 历史。
- 决策：测试二进制放入 `.tools/ffmpeg/bin` 并加入 `.gitignore`。
- 原因：保持仓库体积合理；最终发布时会通过 Release 或安装包提供运行时文件。

## DR-012 文件和拖拽共用导入服务

- 状态：已接受
- 背景：按钮选择和拖拽导入需要相同的格式检查、去重和错误处理。
- 决策：两种入口统一调用 `VideoImporter`，界面只负责收集路径和展示结果。
- 原因：避免两套逻辑产生不同行为，并为后续批量任务复用导入规则。

## DR-013 使用扩展名白名单拦截不支持文件

- 状态：已接受
- 背景：此阶段尚未调用 ffprobe，无法通过媒体流判断文件是否真正可解码。
- 决策：先使用常见视频扩展名白名单和文件系统检查，真实解码验证放在读取信息阶段。
- 原因：保证导入响应快速，同时避免对每个文件启动外部进程。

## DR-014 导入任务不跨会话保存

- 状态：已被 DR-026 取代
- 背景：源文件可能在应用关闭期间被移动或删除。
- 决策：本阶段任务只保存在当前会话，不持久化任务列表。
- 原因：避免应用启动后恢复无效任务，后续需要时再设计任务历史。

## DR-015 使用内容指纹辅助去重

- 状态：已接受
- 背景：同一视频可能存在不同文件名、空格与下划线差异或复制文件。
- 决策：除规范化路径外，再计算文件大小和首段、中段、尾段采样的 SHA-256 指纹。
- 原因：在不完整读取大文件的前提下，识别同内容不同名称的重复视频。

## DR-016 明确主题化消息框

- 状态：已接受
- 背景：深色主题继承后，QMessageBox 默认浅色按钮与白色文字出现对比缺失。
- 决策：为消息框背景、正文和按钮提供显式主题样式。
- 原因：确保确认操作在浅色和深色主题下都清晰、可操作。

## DR-017 使用 ffprobe JSON 作为媒体信息入口

- 状态：已接受
- 背景：视频轮询需要稳定获取视频流、音频流和容器信息。
- 决策：执行 `ffprobe -print_format json -show_format -show_streams` 并解析 JSON。
- 原因：避免解析面向人的控制台文本，字段结构更稳定，便于测试。

## DR-018 媒体信息按单任务异步读取

- 状态：已接受
- 背景：多个大文件同时执行 ffprobe 会争抢磁盘资源，并可能让任务状态难以对应。
- 决策：使用 QProcess 队列，每次只读取一个任务，完成后再处理下一个。
- 原因：界面保持响应，进度和错误归属明确，也为后续批量转换队列打基础。

## DR-019 缩略图使用多位置回退

- 状态：已接受
- 背景：部分视频在 10% 位置没有可解码帧，或关键帧分布特殊。
- 决策：依次尝试 10%、1 秒、中段、结尾和首帧，任一位置成功即停止。
- 原因：兼顾首屏速度和对不同编码文件的兼容性。

## DR-020 缩略图按内容指纹缓存

- 状态：已接受
- 背景：重复打开同一视频时不应重复执行 ffmpeg。
- 决策：以文件内容指纹作为 JPG 缓存文件名，并在删除任务时清理。
- 原因：避免相同内容重复生成，同时保持缓存与任务生命周期一致。

## DR-021 空状态使用紧凑居中布局

- 状态：已接受
- 背景：隐藏的缩略图控件仍参与垂直空间分配，导致空预览内容被拉散。
- 决策：将图标、标题和提示放入固定高度的提示容器，并在无媒体信息时隐藏重生成按钮。
- 原因：保持空状态紧凑、明确，同时不影响缩略图加载后的底部说明布局。

## DR-022 提高缩略图分辨率和长文件名适配

- 状态：已接受
- 背景：640 像素缩略图在较宽预览区放大后显得模糊，长文件名也会挤压状态区域。
- 决策：缩略图最高生成到 1920 像素、JPEG 质量提升到 1，源视频较小时不放大，
  并将缓存版本升级为 `v3`；文件名使用单行中部省略，悬停显示完整名称。
- 原因：保证高清屏下预览清晰，同时让长文件名保持可识别且不破坏布局。

## DR-023 转换设置与命令参数分离

- 状态：已接受
- 背景：界面选项需要稳定映射到 FFmpeg 参数，并为后续转换执行复用。
- 决策：使用 `ConversionSettings` 描述用户配置，由独立命令生成器构建参数列表。
- 原因：界面、配置持久化和转换执行解耦，命令构建可以独立测试。

## DR-024 格式切换驱动编码选项

- 状态：已接受
- 背景：不同容器支持的视频和音频编码不同，无效组合会在执行阶段失败。
- 决策：切换格式时刷新编码选项和默认值，并按格式禁用不适用的控件。
- 原因：在界面阶段阻止明显无效配置，降低后续转换错误率。

## DR-025 提供只读 FFmpeg 命令预览

- 状态：已接受
- 背景：命令行实现需要让开发者和用户理解最终执行参数。
- 决策：在高级区域显示根据当前设置生成的完整命令预览。
- 原因：便于测试、排错和面试讲解，同时避免用户直接编辑命令。

## DR-026 启动时恢复有效任务

- 状态：已接受
- 背景：用户期望关闭并重开应用后继续处理之前的任务。
- 决策：持久化任务路径，启动时重新校验文件存在、格式和内容，只恢复有效任务。
- 原因：保留用户工作进度，同时避免恢复已经移动或删除的无效路径。

## DR-027 禁用参数显示“不适用”

- 状态：已接受
- 背景：音频格式禁用视频参数后，控件仍显示 MP4 模式下遗留的分辨率和帧率。
- 决策：切换不适用格式时清空选项并显示“不适用”，切回视频格式时恢复默认值。
- 原因：避免隐藏参数继续影响用户理解，也避免错误配置被持久化后再次出现。

## DR-028 使用模态卡片解释输出格式

- 状态：已接受
- 背景：不熟悉视频格式的用户需要快速理解兼容性、场景和限制。
- 决策：在目标格式标题旁增加问号按钮，打开包含六种格式说明的模态卡片列表。
- 原因：说明信息与格式选择保持在同一工作流内，同时不占用主界面常驻空间。

## DR-029 复用通用帮助卡片展示高级参数

- 状态：已接受
- 背景：高级参数同样需要卡片化解释，与格式说明具有相同的信息结构。
- 决策：抽取通用 `HelpCardDialog`，分别提供格式说明和高级参数说明数据。
- 原因：统一弹窗视觉与交互，减少重复布局代码，同时保持文案和参数说明独立。

## DR-030 使用用户提供的 SVG 帮助图标

- 状态：已接受
- 背景：原帮助入口使用字符问号和 `i`，视觉不够统一。
- 决策：保留用户提供的 `icon/问号.svg`，并复制为
  `src/video_switch/resources/icons/question.svg` 作为应用资源。
- 原因：使用同一矢量图标统一两个帮助入口，资源路径独立于开发文档目录，
  便于后续打包。

补充：帮助按钮统一为 `18×18`、图标为 `15×15`；标题与图标间距统一为 `4px`。
折叠区域的箭头、标题和帮助按钮拆分为独立控件，避免 Qt 折叠按钮的内部留白
导致图标位置不一致。最初曾取消悬停反馈；后续反馈希望保留灰色提醒，因此
悬停时恢复居中的 `surface_hover` 圆形背景，但不改变尺寸、边框或图标位置。
最终调整为：按钮 `20×20`、图标 `15×15`、无边框；浅色悬停色为
`#e2e8f0`，深色悬停色为 `#394858`，保证图标和背景同中心且两种主题都清晰。
用户复核后仍认为视觉中心偏左上，最终改为按钮自绘悬停圆：
按钮 `22×22`、背景圆 `20×20`、图标 `15×15`，背景向右下偏移 1 像素。

## DR-031 使用项目播放 SVG 并显式水平居中

- 状态：已接受
- 背景：系统播放图标视觉中心不一致，固定宽度图标也在预览布局中默认靠左。
- 决策：复制 `icon/播放.svg` 为 `resources/icons/play.svg`，按固定 `64×64`
  渲染并着色，在预览垂直布局中显式设置 `AlignHCenter`。
- 原因：保证图标资源统一、深浅主题可见，并与标题保持同一条中心线。

## DR-032 使用项目文件 SVG 并显式水平居中

- 状态：已接受
- 背景：任务队列空状态图标视觉中心偏左，固定尺寸标签也受布局默认对齐影响。
- 决策：复制 `icon/文件.svg` 为 `resources/icons/file.svg`，按固定 `48×48`
  渲染并按主题着色，在空状态布局中显式设置 `AlignHCenter`。
- 原因：统一任务队列图标资源，使其与“队列为空”标题保持同一条中心线。

## DR-033 使用项目视频 SVG 作为添加按钮图标

- 状态：已接受
- 背景：系统文件夹图标与“添加视频”文字视觉高度不一致，影响按钮对齐。
- 决策：复制 `icon/视频.svg` 为 `resources/icons/video.svg`，按 `15×15`
  渲染为白色主题图标，并设置相同尺寸的按钮图标区域。
- 原因：图标高度与文字一致，由按钮统一定义垂直中心，避免系统图标自身留白。

补充：按钮最终改为自绘背景之上的图标和文字。文字保持居中，图标高度使用
`fontMetrics().height()`，图标中心取“按钮左边框到第一个字中心”的中点，
避免依赖 Qt 按钮默认内容布局。图标同时使用 DPI 感知渲染。
后续复核认为整体右侧留白过大，最终改为“4px 左边距 + 图标 + 6px + 文字 +
一个首字符宽度右边距”，按钮宽度由字体测量动态计算；之后仅将左边距增加到
8px，其余布局保持不变。

## DR-034 使用项目 SVG 替换顶部工具按钮

- 状态：已接受
- 背景：系统垃圾桶、显示器和设置图标与灰色悬停背景视觉中心不一致。
- 决策：复制 `垃圾桶.svg`、`切换.svg`、`设置.svg` 到应用资源；使用专用
  `AssetIconButton`，按钮 `34×34`、图标 `18×18`、悬停背景 `30×30`。
- 原因：图标和背景由同一按钮绘制，背景向右下偏移 1 像素，解决视觉中心偏移，
  并保证浅色和深色主题都清晰。

补充：输出目录和恢复默认按钮也替换为 `文件夹.svg`、`刷新.svg`，并复用
`AssetIconButton` 的自绘悬停背景和 DPI 感知渲染。

补充：重新生成缩略图按钮同样使用 `刷新.svg`；`AssetIconButton` 直接绘制
DPI 感知位图，而不是交给 QIcon 状态着色，确保浅色和深色主题颜色一致。

补充：任务列表条目同样使用项目 `file.svg` 图标，按 24px 逻辑尺寸和 DPI
感知方式渲染，避免系统文件图标在不同主题下样式不一致。

## DR-037 输出路径悬停滚动

- 状态：已接受
- 背景：较长的输出路径在只读文本框中显示不完整，用户需要能够查看完整路径。
- 决策：使用自绘 `MarqueeLineEdit`；鼠标进入时按固定像素速度向左滚动，
  到达末尾后从起点循环，鼠标离开后停止并恢复默认显示。
- 原因：不改变默认界面布局，同时提供完整的路径查看能力。

## DR-038 禁止滚轮误改转换参数

- 状态：已接受
- 背景：鼠标停在 QComboBox 或 QSpinBox 上滚动时，可能意外改变画质、分辨率、
  帧率、编码或 CRF。
- 决策：主窗口安装滚轮事件过滤器，拦截所有下拉框和数值框的 Wheel 事件。
- 原因：避免用户在滚动右侧设置区域时误改参数，点击、键盘和下拉选择不受影响。

## DR-039 使用项目 SVG 作为应用图标

- 状态：已接受
- 背景：默认窗口图标仍是 Qt 系统图标。
- 决策：复制 `icon/应用图标.svg` 为 `resources/icons/app.svg`，同时设置到
  `QApplication` 和主窗口。
- 原因：窗口标题栏、任务栏和后续打包配置使用统一的应用标识；SVG 在可用位置
  保持矢量清晰度。

## DR-040 不支持文件使用明确弹窗提示

- 状态：已接受
- 背景：仅依靠底部状态栏时，用户拖入不支持文件容易认为应用没有响应。
- 决策：文件和拖拽导入遇到不支持或无法访问的文件时弹出“文件未导入”对话框，
  显示支持格式、文件名和具体失败原因。
- 原因：明确说明为什么没有加入队列，同时允许同一批中的有效视频继续导入。

## DR-041 使用 QProcess 执行单文件转换

- 状态：已接受
- 背景：需要真正执行 FFmpeg，同时保持界面响应并支持实时进度和取消。
- 决策：新增 `ConversionRunner`，一次执行一个 QProcess，解析 `-progress pipe:1`。
- 原因：进程隔离清晰，可实时读取速度和输出时间，也便于取消和清理输出文件。

## DR-042 使用取消后延迟强杀和输出清理

- 状态：已接受
- 背景：FFmpeg 退出可能需要时间，强制退出可能留下不完整文件。
- 决策：先发送终止请求，1500ms 后仍未退出则强制结束，并删除未完成输出。
- 原因：兼顾正常退出机会和界面响应，避免留下损坏文件。

## DR-043 转换完成结果提供文件操作入口

- 状态：已接受
- 背景：转换完成后用户需要确认并访问结果文件。
- 决策：成功时显示输出文件名和大小，并提供打开文件、打开目录按钮。
- 原因：完成转换后可以直接进入下一步操作，不需要手工寻找输出位置。

## DR-044 防止右侧设置区横向截断

- 状态：已接受
- 背景：部分 DPI 和窗口宽度下，格式按钮、下拉框和输出路径会超出滚动区宽度。
- 决策：滚动区使用按需横向滚动；格式按钮允许收缩；组合框使用
  `AdjustToMinimumContentsLengthWithIcon` 并降低最小内容长度。
- 原因：正常情况下不出现横向滚动条，异常窗口宽度下也不会永久截断控件。

## DR-035 SVG 图标按设备像素比渲染

- 状态：已接受
- 背景：SVG 先固定渲染成低像素位图后，在 Windows 125%、150% 或 200% 缩放下
  会被系统再次放大，产生模糊。
- 决策：使用屏幕 `devicePixelRatio` 计算物理像素，例如 18px 逻辑图标在 200%
  下生成 36×36; 将 `QPixmap.devicePixelRatio` 设为对应倍率，并在 DPR 变化时
  重新渲染。Qt 高 DPI 舍入策略使用 `PassThrough`。
- 原因：保持 SVG 的矢量细节，避免高 DPI 屏幕二次缩放，无需下载更大的图标。

## DR-036 统一粗体字重和字体 hinting

- 状态：已接受
- 背景：界面粗体标题在截图和部分缩放比例下边缘发软，QSS 同时使用了
  `650/800` 等非标准字重。
- 决策：应用启动时设置 `Microsoft YaHei UI` 13px、全像素 hinting、抗锯齿和
  kerning；QSS 字重统一为实际 Bold 字面可匹配的 `600/700`。
- 原因：减少字体合成和字重近似，使用系统真实 Bold 字形，提升中文粗体边缘清晰度。
