# 开发决策记录

本文档记录项目中的关键选择、原因、备选方案和用户反馈。后续每个步骤继续追加，
不覆盖旧记录。

## DR-001 使用桌面客户端

- 状态：已接受
- 背景：审核会优先查看界面选型，纯网页方案不符合客户端关联要求。
- 决策：使用 PySide6 构建桌面客户端。
- 原因：当前项目为 Python，桌面能力和本地文件处理直接，开发风险低于 Electron
  或 Tauri。

## DR-002 使用 FFmpeg 命令行

- 状态：已接受
- 背景：题目允许通过 ffmpeg 命令行完成转换。
- 决策：使用 ffmpeg/ffprobe 可执行文件，不接入 FFmpeg API。
- 原因：开发速度快、进程隔离清晰、无需编译原生库。

## DR-003 不在运行时调用远程 API

- 状态：已接受
- 背景：题目要求使用 AI 辅助开发，没有要求应用提供在线 AI 功能。
- 决策：应用完全本地运行，不调用大模型、云转换或账号 API。
- 原因：保护视频隐私、避免密钥和服务器成本、降低演示失败风险。

## DR-004 使用 PySide6-Essentials

- 状态：已接受
- 背景：完整 PySide6 包含 WebEngine、PDF 和 Addons，体积较大。
- 决策：只安装 PySide6-Essentials。
- 原因：Qt Widgets、QtCore、QtGui 和 QProcess 已覆盖当前项目需求。

## DR-005 使用 uv 管理环境

- 状态：已接受
- 背景：用户使用 uv，并且需要可复现依赖。
- 决策：使用 `pyproject.toml` 和 `uv.lock`。
- 原因：环境初始化、依赖锁定和命令执行统一。

## DR-006 使用三栏式桌面工作区

- 状态：已接受
- 背景：应用同时存在任务队列、视频信息和转换设置三个主要工作区域。
- 决策：采用左侧任务队列、中间视频信息、右侧转换设置的单窗口布局。
- 原因：用户可以在一个界面内完成检查、配置和执行，不需要频繁跳转页面。

## DR-007 提供浅色和深色主题

- 状态：已接受
- 背景：桌面工具需要在不同使用环境下保持清晰和舒适。
- 决策：浅色主题作为默认主题，深色主题通过顶部按钮切换并保存。
- 原因：提高界面完成度，并验证所有自定义控件具备清晰的主题对比。

## DR-008 显式注册 Windows 中文字体

- 状态：已接受
- 背景：Qt 在部分运行环境中无法自动发现 Windows 中文字体。
- 决策：启动时尝试注册系统的 Microsoft YaHei 字体文件。
- 原因：避免中文界面出现方框或缺字，同时仍使用系统字体，不额外分发字体文件。

## DR-009 FFmpeg 使用分层查找

- 状态：已接受
- 背景：开发环境和最终打包环境的工具位置不同，用户也可能已经安装 FFmpeg。
- 决策：依次查找用户配置路径、应用内置目录、开发工具目录和系统 PATH。
- 原因：兼顾可移植性、离线运行和用户手动修复。

## DR-010 异步验证工具版本

- 状态：已接受
- 背景：执行外部程序可能失败或长时间无响应，同步检测会阻塞界面。
- 决策：使用 QProcess 异步执行 `ffmpeg -version` 和 `ffprobe -version`，并设置超时。
- 原因：保证检测过程界面保持响应，同时统一处理路径错误和版本异常。

## DR-011 开发用 FFmpeg 不提交仓库

- 状态：已接受
- 背景：完整 FFmpeg 二进制体积较大，不适合直接进入 Git 历史。
- 决策：测试二进制放入 `.tools/ffmpeg/bin` 并加入 `.gitignore`。
- 原因：保持仓库体积合理；最终发布时会通过 Release 或安装包提供运行时文件。

## DR-012 文件和拖拽共用导入服务

- 状态：已接受
- 背景：按钮选择和拖拽导入需要相同的格式检查、去重和错误处理。
- 决策：两种入口统一调用 `VideoImporter`，界面只负责收集路径和展示结果。
- 原因：避免两套逻辑产生不同行为，并为后续批量任务复用导入规则。

## DR-013 使用扩展名白名单拦截不支持文件

- 状态：已接受
- 背景：此阶段尚未调用 ffprobe，无法通过媒体流判断文件是否真正可解码。
- 决策：先使用常见视频扩展名白名单和文件系统检查，真实解码验证放在读取信息阶段。
- 原因：保证导入响应快速，同时避免对每个文件启动外部进程。

## DR-014 导入任务不跨会话保存

- 状态：已被 DR-026 取代
- 背景：源文件可能在应用关闭期间被移动或删除。
- 决策：本阶段任务只保存在当前会话，不持久化任务列表。
- 原因：避免应用启动后恢复无效任务，后续需要时再设计任务历史。

## DR-015 使用内容指纹辅助去重

- 状态：已接受
- 背景：同一视频可能存在不同文件名、空格与下划线差异或复制文件。
- 决策：除规范化路径外，再计算文件大小和首段、中段、尾段采样的 SHA-256 指纹。
- 原因：在不完整读取大文件的前提下，识别同内容不同名称的重复视频。

## DR-016 明确主题化消息框

- 状态：已接受
- 背景：深色主题继承后，QMessageBox 默认浅色按钮与白色文字出现对比缺失。
- 决策：为消息框背景、正文和按钮提供显式主题样式。
- 原因：确保确认操作在浅色和深色主题下都清晰、可操作。

## DR-017 使用 ffprobe JSON 作为媒体信息入口

- 状态：已接受
- 背景：视频轮询需要稳定获取视频流、音频流和容器信息。
- 决策：执行 `ffprobe -print_format json -show_format -show_streams` 并解析 JSON。
- 原因：避免解析面向人的控制台文本，字段结构更稳定，便于测试。

## DR-018 媒体信息按单任务异步读取

- 状态：已接受
- 背景：多个大文件同时执行 ffprobe 会争抢磁盘资源，并可能让任务状态难以对应。
- 决策：使用 QProcess 队列，每次只读取一个任务，完成后再处理下一个。
- 原因：界面保持响应，进度和错误归属明确，也为后续批量转换队列打基础。

## DR-019 缩略图使用多位置回退

- 状态：已接受
- 背景：部分视频在 10% 位置没有可解码帧，或关键帧分布特殊。
- 决策：依次尝试 10%、1 秒、中段、结尾和首帧，任一位置成功即停止。
- 原因：兼顾首屏速度和对不同编码文件的兼容性。

## DR-020 缩略图按内容指纹缓存

- 状态：已接受
- 背景：重复打开同一视频时不应重复执行 ffmpeg。
- 决策：以文件内容指纹作为 JPG 缓存文件名，并在删除任务时清理。
- 原因：避免相同内容重复生成，同时保持缓存与任务生命周期一致。

## DR-021 空状态使用紧凑居中布局

- 状态：已接受
- 背景：隐藏的缩略图控件仍参与垂直空间分配，导致空预览内容被拉散。
- 决策：将图标、标题和提示放入固定高度的提示容器，并在无媒体信息时隐藏重生成按钮。
- 原因：保持空状态紧凑、明确，同时不影响缩略图加载后的底部说明布局。

## DR-022 提高缩略图分辨率和长文件名适配

- 状态：已接受
- 背景：640 像素缩略图在较宽预览区放大后显得模糊，长文件名也会挤压状态区域。
- 决策：缩略图最高生成到 1920 像素、JPEG 质量提升到 1，源视频较小时不放大，
  并将缓存版本升级为 `v3`；文件名使用单行中部省略，悬停显示完整名称。
- 原因：保证高清屏下预览清晰，同时让长文件名保持可识别且不破坏布局。

## DR-023 转换设置与命令参数分离

- 状态：已接受
- 背景：界面选项需要稳定映射到 FFmpeg 参数，并为后续转换执行复用。
- 决策：使用 `ConversionSettings` 描述用户配置，由独立命令生成器构建参数列表。
- 原因：界面、配置持久化和转换执行解耦，命令构建可以独立测试。

## DR-024 格式切换驱动编码选项

- 状态：已接受
- 背景：不同容器支持的视频和音频编码不同，无效组合会在执行阶段失败。
- 决策：切换格式时刷新编码选项和默认值，并按格式禁用不适用的控件。
- 原因：在界面阶段阻止明显无效配置，降低后续转换错误率。

## DR-025 提供只读 FFmpeg 命令预览

- 状态：已接受
- 背景：命令行实现需要让开发者和用户理解最终执行参数。
- 决策：在高级区域显示根据当前设置生成的完整命令预览。
- 原因：便于测试、排错和面试讲解，同时避免用户直接编辑命令。

## DR-026 启动时恢复有效任务

- 状态：已接受
- 背景：用户期望关闭并重开应用后继续处理之前的任务。
- 决策：持久化任务路径，启动时重新校验文件存在、格式和内容，只恢复有效任务。
- 原因：保留用户工作进度，同时避免恢复已经移动或删除的无效路径。

## DR-027 禁用参数显示“不适用”

- 状态：已接受
- 背景：音频格式禁用视频参数后，控件仍显示 MP4 模式下遗留的分辨率和帧率。
- 决策：切换不适用格式时清空选项并显示“不适用”，切回视频格式时恢复默认值。
- 原因：避免隐藏参数继续影响用户理解，也避免错误配置被持久化后再次出现。

## DR-028 使用模态卡片解释输出格式

- 状态：已接受
- 背景：不熟悉视频格式的用户需要快速理解兼容性、场景和限制。
- 决策：在目标格式标题旁增加问号按钮，打开包含六种格式说明的模态卡片列表。
- 原因：说明信息与格式选择保持在同一工作流内，同时不占用主界面常驻空间。

## DR-029 复用通用帮助卡片展示高级参数

- 状态：已接受
- 背景：高级参数同样需要卡片化解释，与格式说明具有相同的信息结构。
- 决策：抽取通用 `HelpCardDialog`，分别提供格式说明和高级参数说明数据。
- 原因：统一弹窗视觉与交互，减少重复布局代码，同时保持文案和参数说明独立。
